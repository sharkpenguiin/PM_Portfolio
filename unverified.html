웰던프로덕트ERP 기획2026.04–2026.06

미확정 매출자료 처리

확인되지 않은 자료는 시스템이 단정하지 않도록 설계했습니다.

  • 본인 역할확인 대상 처리 방식 설계
  • 기획 범위ERP·협력사 포털, 18개 업무 영역 단독 기획
  • 진행 상태리뷰 확정

미등록 정보와 중복 의심 자료를 나눠 사람이 확인하도록 설계했습니다.

  1. 01상황과 문제미등록이나 같은 값만으로는 확정·삭제할 수 없었습니다.
  2. 02해결가등록과 의심 표시로 나눠 사람이 확인하도록 설계했습니다.
  3. 03결과고객사·디자인 리뷰를 거쳐 확정했습니다.
01

상황과 문제

확인한 상황확인되지 않은 매출자료

  • 실제 거래 중인 약국도 정보가 갱신되지 않아 미등록으로 나타날 수 있었습니다. 미등록 약국은 신생 약국일 수도 있습니다.
  • 날짜·제품·약국·수량이 같아도 실제 중복이라고 단정할 수 없었습니다.
02

해결

마스터에 없거나 값이 같다는 이유만으로 확정·삭제하지 않고, 미등록 정보와 중복 의심 자료를 나눠 확인하도록 설계했습니다.

미등록 약국

택하지 않은 처리

자동 확정

미등록 약국 → 바로 확정

검증되지 않은 정보가 그대로 쓰일 수 있다

기획한 흐름

가등록 후 확인

  1. 1 가등록으로 보관명칭·사업자번호·주소
  2. 2 확인 전 사용 보류임시저장, 거래 처리 화면 미노출
  3. 3 사람이 확인 후 확정확정

택하지 않은 처리

자동 삭제

실제 중복이 아닌 행도 지워질 수 있다

→
기획한 흐름

표시 후 담당자 판단

  1. 1 중복 의심 표시확인할 대상
  2. 2 담당자가 확인실제 중복 여부 판단

설명 도식. 고객사 리뷰·디자인 리뷰를 거쳐 정한 처리 흐름을 다시 그린 그림입니다.

03

결과

리뷰 확정

고객사 리뷰와 디자인 리뷰를 거쳐 처리 흐름과 가등록 필수값을 확정했습니다.

  • 결정로그도매 매출 관리 결정에 "중복은 의심으로만 표시"로 남김

출시 후 사용 효과를 측정한 사례는 아닙니다.

결정로그

“업체별로 나누지 않고 일괄 업로드한 뒤 검증 · 오류는 유형별 건수로 표시 · 중복은 의심으로만 표시”

도매 매출 관리 결정 · 원문을 재구성. 매출자료 검증 상세에도 같은 기록을 실었습니다.

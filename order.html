웰던프로덕트ERP 기획2026.04–2026.06

ERP 구축 순서 조정

정산 자료를 마스터데이터로 분류하는 구조라서, 정산부터 만들도록 순서를 바꿨습니다.

  • 본인 역할업무 구조 확인·순서 제안
  • 기획 범위ERP·협력사 포털, 18개 업무 영역 단독 기획
  • 진행 상태합의 → 개발 진행

내부 실무자·TF 담당자와 업무를 확인하고, 정산 기능을 먼저 구축하는 방안을 고객사에 제안했습니다.

  1. 01상황과 문제업무를 확인하며 정산 자료가 출발점인 구조를 파악했습니다.
  2. 02해결정산 흐름부터 구체화하도록 순서를 바꿨습니다.
  3. 03결과고객사와 합의해 정산 기능부터 개발이 진행됐습니다.
01

상황과 문제

처음 가정마스터데이터 화면부터 만드는 순서

  • 처음에는 기존 마스터데이터를 기준으로 삼고 들어오는 EDI 자료를 분류한다고 보고, 마스터데이터 화면부터 만드는 순서였습니다.
  • 내부 실무자·TF 담당자와 업무를 확인하며, 정산을 위해 받은 자료를 EDI 자료와 함께 정산에 쓰는 구조를 파악했습니다.
02

해결

마스터데이터 화면보다 정산에 필요한 자료의 분류·연결 흐름을 먼저 구체화해야 한다고 판단했습니다.

자료 처리 흐름자료 검증 흐름과 개발 순서의 차이

  1. 1EDI 수신
  2. 2심평원 검증
  3. 3마스터데이터 등록

덧붙임 EDI 수신 → 심평원 검증 → 마스터데이터 등록은 자료 처리 흐름입니다. 정산 기능을 먼저 구축했다는 것은 마스터데이터 없이 정산한다는 뜻이 아닙니다.

같은 판단을 적용한 요청병의원 통합 조회

이 요청도 개발은 미루고, 화면 검토부터 했습니다.

요청
병의원 정보를 한 번에 조회, 취급 약품·배치된 의약품 영업대행사(CSO)로 진입 가능 여부 판단
제약
EDI·정산 기능이 먼저 필요하고, 연결 구조가 복잡해 바로 개발하기 어려움
판단
개발은 미루고, 화면 검토는 먼저. 선행 조건 정리 후 프로토타입 제작
산출물
고객사와 검토한 프로토타입. 작동 방식을 확인하고 후속 개발 준비
03

결과

합의 → 개발 진행

정산 기능을 먼저 구축하는 방안을 고객사에 제안해 개발 순서를 조정했습니다.

  • 개발 순서 조정정산 → 마스터데이터 → 협력사 포털
  • 개발 진행재직 중 정산 기능부터 개발
  • 병의원 통합 조회고객사와 검토한 프로토타입

출시 후 사용 효과를 측정한 사례는 아닙니다.

후속 검증을 위한 제안 지표 (미측정)
  • 마스터데이터 구축 단계에서 생긴 구조 변경·재작업 건수
  • 계획 대비 정산 기능 일정

EDI

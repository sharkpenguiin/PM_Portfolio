02문제 발견

입력 후 오류 원인을 다시 찾는 업무

거래처 자료는 이메일·우편·카카오톡으로 내부 실무자에게 전달됐습니다. 실무자가 파일을 취합하고 엑셀로 정리해 입력하는 과정에서 자료 중복·누락과 잘못 전달된 자료를 확인해야 했습니다.

EDI 작업은 여러 메뉴에 흩어져 있었고, 입력값이 틀렸는지 원본 자료에 문제가 있는지 확인하려면 자료를 다시 대조해야 했습니다. 매출자료에서는 같은 제품코드 오류가 여러 업체에 반복됐습니다.

같은 제품코드 오류가 업체마다 반복돼서, 오류별로 모아 한 번에 처리하게 바꿨습니다.

확인 단위

업체별오류별

발견 시점

정산할 때업로드할 때

어떻게 확인하고 진행했나

  1. 배경미매칭 자료는 정산에서 빠진 뒤 금액 대조로 발견됐고, 보완된 내역은 다음 달 이후 정산으로 넘어갔습니다.
  2. 무엇오류 단위로 모아 판단하게 하고, 업로드할 때 제품이 연결되지 않는 항목을 표시했습니다. 자료가 돌아오는 시점은 통제할 수 없어 이월 반영은 유지했습니다.
  3. 합의여러 업체 자료를 모아 검토·일괄 처리하는 방식을 제가 기획해 제안했고, 고객사 리뷰에서 처리 방향을 합의해 결정로그에 남겼습니다.
오류 유형과 처리 기능

사업자번호·매출일자 누락, 제품 매칭 실패를 유형별 건수로 표시하고 영향 업체와 오류 사유를 보여줬습니다. 일괄 매칭·자료 재요청·중복 확인으로 연결하고, 자료 보완이 필요하면 도매업체에 다시 요청하도록 했습니다.

  3. 합의정산 기능을 먼저 구축하는 방안을 고객사에 제안해 정산 → 마스터데이터 → 협력사 포털 순으로 조정했습니다.

  2. 제약EDI·정산 기능이 먼저 필요연결 구조가 복잡해 바로 개발하기 어려움
  3. 판단개발은 미루고, 화면 검토는 먼저선행 조건 정리 후 프로토타입 제작
  4. 산출물고객사와 검토한 프로토타입작동 방식을 확인하고 후속 개발 준비

증빙 확인 방식

모달별도 창

수량 값

한 칸수신값·확정값 분리

어떻게 확인하고 진행했나

  1. 배경입력 과정의 오류인지 원본 자료의 문제인지 구분하기 어려워, 원본과 대조하며 판단할 흐름이 필요했습니다.
  2. 무엇OCR로 품목·수량을 자동 입력하고, 당월 수량(수신값)과 확정수량(증빙 대조 후 확정한 값)을 나눴습니다.
  3. 합의모달과 별도 창을 비교해 고객사와 별도 창으로 정하고, 프로토타입·PRD에 반영했습니다.
탐색 흐름과 세부 정책

원본 증빙 이미지에서 OCR로 품목·수량을 읽어 자동 입력하고, 실무자가 대조해 보정·확정하는 흐름으로 정리했습니다. 여러 메뉴에 흩어진 EDI 작업은 거래처 → 병의원 → 품목 순으로 탐색하며 대조·보정·확정하도록 연결했습니다.

왜, 무엇을, 어떻게 합의했나

  1. 왜직접 선택하는 화면은 선택지를 미리 제한할 수 있지만, 외부 자료는 들어온 뒤에야 확인할 수 있습니다.
  2. 무엇자료 전달 경로를 포털로 모아 거래처가 직접 올리게 하고, 실무자는 취합·입력 대신 대조·보정·확정을 맡게 역할을 나눴습니다.
  3. 합의입력 경로별 검증 방식을 고객사 리뷰에서 합의하고 요구사항 명세에 반영했습니다.
거래처와 실무자의 역할 분리

기존에는 거래처 자료가 이메일·우편·카카오톡으로 내부 실무자에게 전달됐습니다. 자료 전달 경로를 포털로 모으고, 거래처가 직접 자료를 업로드·확인하게 했습니다. 내부 실무자는 전달받은 파일을 다시 취합·입력하는 대신 자료를 대조하고 보정·확정하는 역할로 나눴습니다.

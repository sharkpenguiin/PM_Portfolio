기획재정부 결산시스템 입력 검증

입력 오류를 저장하거나 계산한 뒤에야 알 수 있어서, 입력하는 중에 확인하도록 바꿨습니다.

  • 본인 역할개선안 기획·담당자 합의
  • 추적RFP 요구사항 ↔ 화면·산출물 (RTM)
  • 진행 상태개발 반영·재검증

UT 운영, 개선안 기획·담당자 합의·개발 전달, 수정 결과 재검증, 선행 작업 제안. 계산 로직·백엔드 구현은 개발팀이 수행했습니다.

  1. 01상황과 문제UT에서 저장·계산 뒤에야 오류를 아는 흐름을 확인했습니다.
  2. 02해결입력 중에 확인하게 하고, 계산 로직·백엔드를 앞당겼습니다.
  3. 03결과개발 화면에 반영돼 동작하는 것을 재검증했습니다.
01

상황과 문제

기존 업무저장·계산 뒤에야 아는 오류

  • 각 부처 결산 담당자가 참여한 UT에서, 입력값의 오류를 저장하거나 계산한 뒤에야 확인하는 흐름을 확인했습니다.
  • 개발 결과를 검증하던 중, 개별 화면을 먼저 수정하면 후속 단계의 계산 로직 개선과 백엔드 개편에 따라 같은 화면을 다시 손봐야 할 위험이 있다고 판단했습니다. 후속 단계에 배정된 기간도 더 짧았습니다.
02

해결

반복 오류 사례를 검토해 검증 시점과 안내 방식의 개선안을 만들고, 기획재정부 담당자와 합의해 개발팀에 전달했습니다.

03

결과

개발 반영·재검증

입력 중 오류 확인·종류 안내 기능이 개발 화면에 반영돼 동작하는 것을 재검증했습니다.

  • 앞당긴 작업계산 로직 개선·백엔드 개편. 제안, 계획 반영, 재직 중 완료
  • 후속으로 조정반복 작업·일부 화면 수정

UT·재검증 방식반복 오류 사례 검토 → 개선안 합의 → 개발팀 전달 → 수정 화면 재검증

UT에서는 기존 검증 항목에 직접 만든 항목을 더해 확인했고, 발견한 오류·버그는 개발자에게 전달한 뒤 같은 항목을 다시 확인했습니다.

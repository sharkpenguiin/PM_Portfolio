웰던프로덕트ERP 기획2026.04–2026.06

매출자료 검증 단위 변경

같은 제품코드 오류가 업체마다 반복돼서, 오류별로 모아 한 번에 처리하도록 설계했습니다.

  • 본인 역할처리 방식 기획·제안
  • 기획 범위ERP·협력사 포털, 18개 업무 영역 단독 기획
  • 진행 상태기획·고객사 합의

여러 업체 자료를 모아 검토·일괄 처리하는 방식을 제가 기획해 제안했습니다.

  1. 01상황과 문제같은 오류를 업체 수만큼 반복 확인했습니다.
  2. 02해결오류별로 모으고, 업로드할 때 표시하도록 기획했습니다.
  3. 03결과고객사 리뷰에서 처리 방향을 합의했습니다.
01

상황과 문제

기존 업무같은 오류를 업체마다 다시 확인

  • 매출자료에서는 같은 제품코드 오류가 여러 업체에 반복됐고, 같은 오류를 업체 수만큼 반복 확인했습니다.
  • 미매칭 자료는 정산에서 빠진 뒤 금액 대조로 발견됐고, 보완된 내역은 다음 달 이후 정산으로 넘어갔습니다.
02

해결

오류 단위로 모아 판단하도록 하고, 업로드할 때 제품이 연결되지 않는 항목을 표시하도록 기획했습니다.

업로드할 때 표시하고 보완을 요청하도록 기획

설명 도식. 처리 방식을 비교하려고 다시 그린 그림입니다.

기획한 화면오류 유형별 건수, 영향 업체, 오류 사유를 한 화면에

  • 사업자번호·매출일자 누락, 제품 매칭 실패를 유형별 건수로 표시하고 영향 업체와 오류 사유를 보여 주도록 화면을 기획했습니다. 일괄 매칭·자료 재요청·중복 확인으로 연결하고, 자료 보완이 필요하면 도매업체에 다시 요청하도록 기획했습니다.

남긴 예외 자료가 돌아오는 시점은 통제할 수 없어 이월 반영은 유지했습니다.

03

결과

기획·고객사 합의

고객사 리뷰에서 처리 방향을 합의해 결정로그에 남겼습니다.

  • 프로토타입매출자료 통합 검증 화면. 오류 유형별 건수, 영향 업체, 일괄 처리
  • 결정로그도매 매출 관리 결정. 일괄 업로드 후 검증, 중복은 의심으로만 표시

기획하고 고객사와 합의한 단계까지 진행했습니다. 출시 후 사용 효과를 측정한 사례는 아닙니다.

01 · 발견한 문제

빠르게 나온 초안에도
확인할 근거가 필요했습니다.

AI 명세 초안에 원래 요구에 없던 자동 승인 옵션이 추가됐습니다. 모달로 구상한 입력 방식이 새 페이지로 표현되기도 했습니다. 결과물을 직접 수정해야 했고, 팀의 확정 자료는 노션 여러 곳에 흩어져 있었습니다.

02 · 검수 기준

원문과 대조하는 절차를
작업 지침에 넣었습니다.

회의록·요구 목록에서 자동 승인의 근거가 없음을 확인하고 명세에서 삭제했습니다. 초기에는 AI 검수 뒤 제가 다시 확인하며 지침을 보완했습니다.

스킬 지침에 반영한 다섯 가지 기준
  • 요구에 없는 기능·정책이 추가됐는지
  • 같은 요구가 반복되거나 상충하는지
  • 시스템 처리와 사용자 판단의 경계
  • 현업 작업 순서와 화면 흐름
  • 문서·화면 사이 필드·상태·규칙의 정합성

03 · 작업 흐름과 지식 조회

근거부터 정리하고,
출처를 함께 확인하게.

회의 내용·요구사항을 먼저 정리한 뒤 PRD, 프로토타입·상세 명세 순으로 작업하도록 구성했습니다. 슬랙 Q&A 봇은 선정한 최신·확정 문서를 참조하고 출처를 표시하도록 했습니다. 근거가 없으면 확인 불가로 안내하도록 설정했습니다.

AI 결과를 근거로 검증하고, 팀이 함께 쓰게 했습니다. 산출물 검수 기준을 먼저 세우고, 회의 기록에서 PRD·프로토타입으로 이어지는 작업과 프로젝트 지식 조회에 AI를 적용했습니다.

01

상황과 문제

발견한 문제명세 초안과 팀 자료에서 본 문제

  • 명세 초안에 원래 요구에 없던 '자동 승인' 옵션이 들어갔습니다.
  • 초기 AI 명세에는 의도한 화면 동작과 다른 내용이 들어가, 결과물을 직접 수정해야 했습니다. 예: 모달로 구상한 입력 방식이 새 페이지로 표현됨
  • 팀원마다 알고 있는 정보와 확정사항이 달랐고, 노션 자료가 여러 곳에 흩어져 찾는 데 시간이 걸렸습니다.
02

해결

원문 요구사항과 대조하는 절차와 5대 검증 기준을 스킬 지침에 넣었습니다. 초기에는 AI 검수 뒤 제가 다시 확인하며 지침을 보완했습니다.

AI 산출물 검수: 실제로 잡아낸 사례

  1. 발견'자동 승인' 옵션명세 초안에 원래 요구에 없던 기능
  2. 대조회의록·요구 목록과 비교근거가 없음을 확인
  3. 조치명세에서 삭제확정 전에 걸러냄
  4. 규칙화스킬 지침 수정다음 검수에서 확인하도록

  3. 자동/수동 경계시스템 처리와 사용자 판단 범위
  4. 실제 업무 동선현업 작업 순서와 화면 흐름 대조
  5. 데이터 정합문서·화면 간 필드·상태·규칙

결과

AI 스킬 PM 4명 실사용

Claude 스킬·워크플로 10종을 PM 챕터에 공유해 대표 포함 PM 4명이 사용했고, 퇴사 전 사내 AX 담당자에게 인수인계했습니다.
